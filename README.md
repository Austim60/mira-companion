# mira-companion

一个以长期文字陪伴为目标的虚拟伴侣项目。项目先构建独立的单用户、单角色对话核心，输入和输出均为文字；后续通过独立的通讯适配层接入 QQ 等平台。

## 当前状态

第一版独立文字对话核心已实现：终端交互、角色配置、OpenAI 兼容模型调用、SQLite 原文与状态持久化、近期上下文、失败可见和手动重试。用户偏好与明确纠正支持称呼、回复方式、不愿讨论的话题和事实更正；明确的主动联系暂停与恢复也已保存为独立状态。本地主动联系已有定时检查、模型选择发送或跳过和终端投递；明确的未来事项可保存为有原话来源的待跟进事项，并在到期后优先考虑。QQ 机器人模型回复和一次定时投递已完成初步验证；跨天投递、权限限制及断线恢复仍需实测。完整产品验收仍需长期记忆、迁移和 QQ 正式接入。

首阶段计划涵盖角色设定、对话上下文、私有记忆与纠错、待跟进事项、受控主动联系及角色资料迁移。多角色、微信、语音与形象作为后续方向。

## 本地运行

在 `mira` 虚拟环境中运行，Python 版本至少 3.10。将模型服务信息写入本地 `.env`；复制 `configs/character.example.json` 为 `configs/character.json`，按需调整角色设定。进程环境变量优先于 `.env`。模型接口需兼容 Chat Completions；当前配置的真实模型已通过历史工具调用、回复方式偏好保存和按编号撤销专项测试。

在仓库根目录执行：

```powershell
$env:PYTHONPATH = 'src'
D:\miniconda3\envs\mira\python.exe -m mira.cli chat
```

输入 `/help` 可按“一个命令、一行用法”的顺序查看所有命令。`/retry` 仅重试最近的失败轮次，可能再次产生模型调用及费用。角色配置每轮重新读取；更换稳定的 `character_id` 会被拒绝。聊天原文保存在本地 SQLite，`.env`、个人角色配置和数据库均被 Git 忽略。

可在聊天中直接表达“以后叫我小墨”等要求，模型会自行判断是否调用偏好工具；只有工具成功后，规则才会持久保存。也可使用以下斜杠写法明确表达意图：这些偏好请求同样交给模型，由模型决定工具调用并给出最终回复。`/help`、`/status`、`/retry` 和 `/exit` 属于终端控制，不发送给模型。

| 输入示例 | 作用 |
| --- | --- |
| `/name 小墨` | 请 Mira 以后称呼你为“小墨”；不会修改 Mira 的名字。 |
| `/style 请简短回答` | 请 Mira 调整回复你的方式。 |
| `/avoid 考研` | 请 Mira 记住你不希望讨论的话题。 |
| `/correct 面试在下午三点 => 面试改为下午四点` | 请 Mira 更正当前事实；不会删除原始聊天。 |
| `/preferences` | 请 Mira 查看已保存的规则及编号。 |
| `/remove 1` | 请 Mira 按编号撤销一条规则。 |

`/preferences` 请求模型查看当前有效规则的连续编号，`/remove` 请求模型按该列表位置撤销；撤销前先查询当前编号，以模型调用工具后的结果为准。更正会优先于近期聊天中的旧说法提供给模型；原始聊天仍保留，长期记忆的纠错与删除属于后续阶段。

可直接说“今天别主动找我”“这周别主动找我”或“先别主动找我”，模型调用工具后分别暂停到本地当天结束、本周日结束或明确恢复为止；说“可以恢复主动联系了”可撤销暂停。暂停期间你仍可主动聊天。含糊的“最近少找我”应先澄清范围。`/status` 可查看授权与暂停状态。恢复不会补发暂停期间错过的消息。

## 本地主动联系

聊天进程启动时会自动启动内部定时检查，退出聊天时停止。输入 `/proactive on` 明确开启主动联系，`/proactive off` 关闭；默认关闭。无需再开一个终端或单独启动任务。

进程每分钟检查一次，只有本地 09:00–22:00 的三个时间窗口会考虑联系；每天最多投递一条，最近六小时聊过天或上一条主动消息尚未收到你的回复时不发送。模型可在合适的窗口选择跳过。主动消息显示在当前聊天终端，不会投递到 QQ。发送结果不确定时不会自动重发。

开启主动联系后，可以直接说“我明天下午三点有面试，结束后你可以问问我结果”。模型会把明确的未来事项、最早联系时间和有效期保存为待跟进候选；到期后优先用于下一次允许的主动检查。说“查看待跟进事项”可让模型列出当前候选；说“面试取消了，不用跟进”或主动告诉它结果，可让模型关闭事项。事项到期、取消或已问过后不再触发同一事项。模型可能漏记或误判，重要安排请在聊天中核对；原话和状态保存在本地数据库。

想立即试模型判断，在当前聊天输入 `/proactive preview`：它使用近期对话生成一条预览或给出跳过原因，不要求开启授权，不受六小时和时间窗口限制，也不会发送或占用当天名额。输入 `/proactive check` 可手动执行一次正式检查，仍会遵守授权、暂停、时段和频率规则；条件允许且模型决定联系时会在当前终端输出消息。

## AstrBot QQ 接入

`integrations/astrbot_mira/` 是 QQ 官方机器人 WebSocket 的 AstrBot 插件：AstrBot 负责接收与发送，Mira 负责对话、资料和主动联系判断。插件只接管配置的一个 QQ 私聊会话，使用与本地终端相同的 `local-user`、角色配置和 SQLite 数据库；不要同时运行本地聊天终端的主动检查。插件内的定时检查随 AstrBot 启停，无需另开 Mira 进程。

在已有的 `astrbot` 环境中安装当前项目，再把插件目录放入 AstrBot 的 `data/plugins/astrbot_mira/`：

```powershell
D:\miniconda3\envs\astrbot\python.exe -m pip install --no-build-isolation --no-deps -e D:\Code\AI_girlfriend\mira-companion
Copy-Item -LiteralPath D:\Code\AI_girlfriend\mira-companion\integrations\astrbot_mira -Destination D:\Code\AI_girlfriend\reference-projects\AstrBot\data\plugins\astrbot_mira -Recurse
```

本机已完成安装、插件复制，并把 `mira_root` 和唯一已记录的 QQ 官方机器人私聊会话写入 AstrBot 的本地插件配置。启动 AstrBot 后，可在 WebUI 的插件配置中核对或更改 `target_umo`，然后重载插件；其他机器需自行选定目标会话。未配置目标会话时插件不会接管消息。模型密钥仍从 Mira 项目根目录的 `.env` 读取，不填入插件配置。

在目标 QQ 私聊中发送普通文字，应只收到 Mira 的回复；本机已完成一次真实 QQ 私聊回复验证，消息在 Mira 数据库中只记录了一轮。发送 `/mira status` 查看状态，`/mira on` 或 `/mira off` 控制主动联系；`/mira preview` 只预览，`/mira check` 按真实时段和频率规则检查。普通对话和主动消息都走 AstrBot 已配置的 QQ 官方机器人通道。重复的平台消息 ID 不会让模型再次回复；平台发送结果不确定时，主动消息不会自动重发。QQ 主动投递的跨天送达、客户端权限和断线恢复仍需实测。

普通对话会把近期消息的发送时间一并交给模型，帮助区分跨天的“今天”和“昨天”。模型可自行调用历史工具，读取本轮之前最近 20 条用户原文及发送时间，再生成最终回复；工具结果不会直接显示为 Mira 的回答。终端命令不计入聊天记录。模型仍可能不调用工具或理解有误，重要回忆需要你核对。

运行自动测试：

```powershell
$env:PYTHONPATH = 'src'
D:\miniconda3\envs\mira\python.exe -m unittest discover -s tests -v
```

如需验证已配置的真实模型是否会自主调用历史工具、保存与撤销偏好、创建和取消待跟进事项，可在 CMD 中运行以下专项测试。它使用临时数据库和合成对话，不读取现有聊天记录，会产生少量模型调用费用：

```bat
set PYTHONPATH=src
set MIRA_LIVE_TEST=1
D:\miniconda3\envs\mira\python.exe -m unittest discover -s tests -p test_live_model.py -v
```

工作区上层的 `reference-projects/` 保存了相关开源项目的本地参考源码；实现遵循本仓库 PRD 和技术设计，没有直接复制第三方代码。
