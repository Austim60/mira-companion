# mira-companion

一个以长期文字陪伴为目标的虚拟伴侣项目。项目先构建独立的单用户、单角色对话核心，输入和输出均为文字；后续通过独立的通讯适配层接入 QQ 等平台。

## 当前状态

第一版独立文字对话核心已实现：终端交互、角色配置、OpenAI 兼容模型调用、SQLite 原文与状态持久化、近期上下文、失败可见和手动重试。当前已开始实现下一阶段的用户偏好与纠正，支持明确称呼、回复方式、不愿讨论的话题和事实更正。QQ 机器人模型回复和一次定时投递已完成初步验证；跨天投递、权限限制及断线恢复仍需实测。完整产品验收仍需长期记忆、主动联系、迁移和 QQ 接入。

首阶段计划涵盖角色设定、对话上下文、私有记忆与纠错、待跟进事项、受控主动联系及角色资料迁移。多角色、微信、语音与形象作为后续方向。

## 本地运行

在 `mira` 虚拟环境中运行，Python 版本至少 3.10。复制 `.env.example` 为 `.env` 并填写模型服务信息；复制 `configs/character.example.json` 为 `configs/character.json`，按需调整角色设定。进程环境变量优先于 `.env`。模型接口需兼容 Chat Completions；当前没有配置真实模型凭据时，无法进行在线试聊。

在仓库根目录执行：

```powershell
$env:PYTHONPATH = 'src'
D:\miniconda3\envs\mira\python.exe -m mira.cli chat
```

输入 `/help` 可按“一个命令、一行用法”的顺序查看所有命令。`/retry` 仅重试最近的失败轮次，可能再次产生模型调用及费用。角色配置每轮重新读取；更换稳定的 `character_id` 会被拒绝。聊天原文保存在本地 SQLite，`.env`、个人角色配置和数据库均被 Git 忽略。

可在聊天中直接表达“以后叫我小墨”等要求，模型会自行判断是否调用偏好工具；只有工具成功后，规则才会持久保存。也可使用以下斜杠写法明确表达意图：这些偏好请求同样交给模型，由模型决定工具调用并给出最终回复。`/help`、`/status`、`/retry` 和 `/exit` 属于终端控制，不发送给模型。

| 输入示例 | 作用 |
| --- | --- |
| `/name 小墨` | 请 Mira 以后称呼你为“小墨”；不会修改 Mira 的名字。 |
| `/style 请简短回答` | 请 Mira 调整回复你的方式。 |
| `/avoid 考研` | 请 Mira 记住你不希望讨论的话题。 |
| `/correct 面试在下午三点 => 面试改为下午四点` | 请 Mira 更正当前事实；不会删除原始聊天。 |
| `/preferences` | 请 Mira 查看已保存的规则及编号。 |
| `/remove 1` | 请 Mira 按编号撤销一条规则。 |

`/preferences` 请求模型查看当前有效规则的连续编号，`/remove` 请求模型按该列表位置撤销；撤销前先查询当前编号，以模型调用工具后的结果为准。更正会优先于近期聊天中的旧说法提供给模型；原始聊天仍保留，长期记忆的纠错与删除属于后续阶段。

普通对话会把近期消息的发送时间一并交给模型，帮助区分跨天的“今天”和“昨天”。模型可自行调用历史工具，读取本轮之前最近 20 条用户原文及发送时间，再生成最终回复；工具结果不会直接显示为 Mira 的回答。终端命令不计入聊天记录。模型仍可能不调用工具或理解有误，重要回忆需要你核对。

运行自动测试：

```powershell
$env:PYTHONPATH = 'src'
D:\miniconda3\envs\mira\python.exe -m unittest discover -s tests -v
```

如需验证已配置的真实模型是否会自主调用历史工具、保存明确的回复方式偏好，以及按列表编号撤销规则，可在 CMD 中运行以下专项测试。它使用临时数据库和合成对话，不读取现有聊天记录，会产生少量模型调用费用：

```bat
set PYTHONPATH=src
set MIRA_LIVE_TEST=1
D:\miniconda3\envs\mira\python.exe -m unittest discover -s tests -p test_live_model.py -v
```

工作区上层的 `reference-projects/` 保存了相关开源项目的本地参考源码；实现遵循本仓库 PRD 和技术设计，没有直接复制第三方代码。
