## AstrBot 历史机器人逻辑

普通对话：QQ 私聊消息 → QQ 官方平台事件 → AstrBot QQ 官方 WebSocket 适配器 → AstrBot 会话与模型调用 → QQ 平台发送回复 → 用户在 QQ 收到回复。

定时测试：用户在 AstrBot 配置未来任务及目标私聊 → 任务到时执行 → AstrBot 通过对应会话投递 → QQ 官方平台 → 用户在 QQ 收到消息。任务是否由模型参与以及实际发送请求字段，本次未以日志或抓包核实。

源码线索：`astrbot/core/platform/sources/qqofficial/qqofficial_platform_adapter.py` 的 `send_by_session` 与 `_send_by_session_common` 按会话构造和发送消息；QQ 私聊分支会移除 `msg_id`。任务实现可从 `astrbot/core/cron/` 和 `astrbot/core/astr_agent_runtime/tools/cron_tools.py` 开始查看。代码支持某条路径不等于实际平台权限不受限制。

## 实测结果与边界

1. 用户报告 QQ 私聊能获得模型生成的回复，基础消息链路通过。
2. 用户报告收到定时任务发来的消息；在本次具体条件下，非新消息触发的定时投递通过。
3. 本次没有核验实际请求、服务端返回、具体间隔、平台状态及用户权限配置，因此不能据此断定具体发送模式或规则；长期未互动、跨天、频控、权限关闭、重启与断线恢复仍待真实测试。
4. 定时投递不等于拟人的主动联系：何时联系、是否打扰、候选话题、角色状态与内容生成的决策均尚未验证。周期检查、事件触发与计划触发可作为候选机制，是否发送仍需单独决策。
5. AstrBot 为已验证的 QQ 通道；一个机器人和单次测试不能证明多角色隔离或长期记忆能力。

## 原 AstrBot 插件接入计划与记录

以《虚拟陪伴产品需求说明书_QQ单角色先行版_v1.6》为产品基准，先设计单角色文字陪伴闭环：固定角色及入口绑定、消息与上下文、角色设定、记忆与更正、待跟进、受控主动联系、资料导出与新环境恢复。消息、记忆和设置保留稳定角色 ID；主动联系默认关闭，遵守安静时段和上限。多角色、微信和语音留待后续阶段。

已选 AstrBot 插件接入：指定 QQ 官方机器人私聊由插件转成 Mira 的 `MessageInput`，消息 ID 用于去重；Mira 保留对话和主动决策数据，AstrBot 负责平台收发。插件在 AstrBot 进程内每分钟检查主动机会，用保存的会话标识调用 AstrBot 发送。插件源码、配置和适配测试位于 `integrations/astrbot_mira/`，已安装到本机 AstrBot 环境并复制到插件目录；唯一已记录的 QQ 私聊会话已写入本地插件配置。2026-11-19 在目标 QQ 私聊发送一条测试文字，用户确认收到 Mira 回复；Mira 数据库中对应一轮 `completed` 记录。主动消息的 QQ 实际投递、跨天发送、权限及断线恢复继续验证，不把单次聊天回复当作完整验收。
