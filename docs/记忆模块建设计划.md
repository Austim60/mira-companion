### 已确定的首版简化与待补项

- 当前任务按轮次排队，每次最多取同一用户与角色的 5 轮；暂歇条件为最近完成对话后 30 分钟，失败约 5 分钟后重试。
- “夜间巩固”当前为本地时间 03:00 后每次检查处理 1 条有版本变化的记录，不是每天仅执行一次。投影由原始来源重建，失败延后约 1 小时重试。
- 计划表中的 hard_rule 通过偏好和授权表实现。记忆事件时间当前沿用来源消息时间，独立有效区间、片段级精确屏蔽、联系扩展一跳、计划状态自动联动及费用金额统计尚待补齐。
- cue 已保存和记入召回诊断，当前低于 gist 档位时不注入正文，也未自动发起二次检索。直接核对来源通过记忆 ID 工具完成。不得把这些待补项登记为完整实现。
- 优先完成正式队列消化、真实跨天召回、更正与忘记验证，再依据失败用例决定是否补强上述能力和调整公式；单角色验证期间继续暂缓多角色。
- 人工整理以独立的类别字段组织展示，不改变模型提取的记忆类型；人工修改记忆类型时才调整对应的基础重要性。合并限定为类型、表达性质相同的已确认记录，并保留两边来源。引用或推测形成的候选须先更正，才能作为有效记忆。忘记仍按整条来源消息屏蔽，同轮含多条记忆时可能影响其他记忆，片段级屏蔽仍待建设。

## 1. 依据、目标与边界

以[单角色先行版 PRD](虚拟陪伴产品需求说明书_QQ单角色先行版_v1.6.md)为当前产品范围，沿用[拟真记忆系统设计](拟真记忆系统设计.md)的短期上下文、交接、近期视图、事件与 USER 事实、联系及可追溯来源。后者涉及多角色和共享的内容属于后续阶段；首轮只交付一个用户、一位角色、一个 QQ 入口，数据仍以稳定的 user_id 和 character_id 归属。

目标是：所有对话都留下可追溯的痕迹；相关时想起，状态变化后能改，用户要求忘记时停止使用；普通旧事逐渐退出日常召回，重要经历保留较长时间。时间衰减控制取用机会和呈现细节，不修改原始证据，也不等同于删除。角色人设、明确边界、称呼禁忌和主动联系授权属于必须生效的规则，不经过普通事件的淡化公式。

现有代码保存原始轮次、偏好、更正、有来源的待跟进事项和长期记忆；暂歇提取、交接、夜间投影、分层召回与来源屏蔽已接入核心服务。普通聊天和 QQ 插件共用这套记忆服务，平台适配层不维护另一份记忆。

## 2. 数据层次与写入原则

| 层次 | 内容 | 权威性与寿命 |
| --- | --- | --- |
| 原始消息 | 用户与助手消息、发生时间、来源及角色归属 | 用户原话是关于用户的证据；按用户的数据删除要求处理 |
| 短期上下文 | 最近原文、当前话题和待回答问题 | 每轮重组，不是独立事实库 |
| 交接 | 跨窗口或重启需要承接的话题、指代与事件 ID | 有来源版本和到期时间，可重建 |
| 事件与 USER 事实 | 有时间、状态、来源和版本的经历或相对稳定资料 | SQLite 权威记录；助手自行生成的内容不能成为用户事实 |
| 概要与线索 | 事件的短描述、主题词和近期检索视图 | 派生投影；源事件变更后失效并重建 |
| 联系 | 同一主题、时间先后、更新、共同经历等有证据的事件边 | 只辅助联想，不凭一条联系创造新事实 |

每条消息都进入处理流；多句普通闲聊可组成同一段日常经历，但每句原话仍可追溯。玩笑、引用和猜测可作为“用户曾这样表达”的经历保存，不升级成其内容为真的用户事实。高度敏感的用户陈述保留原始证据，但在用户明确确认前只作为候选，不自动升为可主动引用的用户事实。夜间反思若提出跨事件的理解，先作为带来源的候选，不自行改写人设或关系定论。

## 3. 标签与状态契约

标签采用相互独立的维度，避免把“私密”“情绪强烈”“重要”和“确定为真”混成一个分数。

| 维度 | 首版值 | 判定用途 |
| --- | --- | --- |
| 内容类型 kind | daily_fragment、interest、user_fact、episode、important_event、shared_experience、plan、hard_rule | 决定基础重要性、时间参数及是否参与衰减 |
| 表达性质 claim_mode | asserted、planned、hypothetical、joke、quote、inferred | 控制可否表述为用户事实；inferred 仅作待核对理解 |
| 事件状态 status | candidate、active、open、resolved、cancelled、disputed、superseded、forgotten | 控制当前有效性；“日常不召回”是查询结果，不是存储状态 |
| 隐私级别 sensitivity | ordinary、private、highly_sensitive | 控制主动提及和展示门槛，不增加重要性 |
| 检索标签 | 主体、话题、对象、事件时间、关联事件 ID | 定位候选与解释联系；关键词本身不是权威事实 |

重要事件须有用户强调、持续影响、明确约定或跨天再次确认等证据；不能因为模型觉得“感人”就提高等级。进行中的计划保留 open 状态及截止时间，完成或取消后转为已结束经历。明确规则走现有偏好和授权路径，可关联记忆来源，但不能因检索未命中而失效。

## 4. 权威记录与派生数据

在现有 messages、turns、user_preferences、follow_ups 上增量扩展，逻辑对象如下；物理表名和字段在数据库迁移前核定。

| 对象 | 最少字段与约束 |
| --- | --- |
| MemoryItem | ID、user_id、character_id、kind、claim_mode、status、subject、content、事件时间、有效区间、importance、sensitivity、version、last_user_evidence_at |
| MemorySource | 记忆 ID、原始消息 ID、可核验的原话片段或片段范围；同一来源与候选类型重放幂等 |
| MemoryEdge | 同域两端 ID、relation、证据来源、状态；端点失效时同步失效 |
| MemoryView | 记忆 ID、detail/gist/cue 层级、文字、来源版本、生成时间；可由权威记录重建 |
| MemoryJob | 待处理消息范围、水位、任务类型、状态、重试次数；停机后可补做且不能重复提交 |
| RecallLog | 查询来源、入选 ID、落选原因、实际注入层级与可确认的使用情况；避免重复记录私人原文 |
| SourceSuppression | 被忘记的来源或片段标识及范围；保留原话时阻止再次提取和召回 |

待跟进事项逐步关联事件 ID。事件结束、取消、更正或忘记时，同一事务更新待跟进状态与相关联系。所有读写先按 user_id、character_id 和有效状态过滤；未来增加角色时不能靠提示词隔离资料。

## 5. 更新时机与任务流程

1. **消息当下。** 继续先保存原话并按平台消息 ID 去重。明确的偏好、边界、纠正、暂停与忘记请求同步处理；成功或失败须在本轮可见。当前回复使用近期原文，不等待夜间任务。
2. **聊天暂歇。** 以最后一条消息后约 30 分钟无新消息作为首版聚合边界，将连续短消息整理为候选事件和短期交接。该时间仅是初值；跨天不等于同一话题必然结束。
3. **夜间巩固。** 每天本地时间约 03:00 处理新增或版本变化的事件，回看近三天的相关来源以发现补充、结果和有证据的联系；生成 detail、gist、cue 投影。没有新消息或变化时不调用模型，也不把旧概要再次作为总结输入。
4. **停机补做。** 按持久化水位补齐未处理的消息范围和错过的夜间任务。生成失败保留原话与任务状态，下次幂等重试；夜间整理不向 QQ 发送消息。
5. **每次召回。** 用当前话题和当前时间计算强度，选择投影；衰减计算不需要每天重写原文或概要。

候选提取输出主体、类型、表达性质、事件时间与时区、原话证据、重要性依据、敏感性和候选联系。程序校验消息归属、引文、时间与状态，再决定新增、补充、更新、争议或仅归入低重要度日常片段；每条原话始终保留在处理流中，模型只有建议权。高优先级规则与删除不能排队等夜间巩固。

## 6. 重要性与召回强度：首版实验参数

以下数字用于实现和回放测试，不代表经验证的人类遗忘规律。重要性 I 在 0～1 之间，由类型基础值及可核验的用户证据决定。

| 内容类型 | 基础 I | 基础半衰期 H0 | 状态约束 |
| --- | ---: | ---: | --- |
| 日常片段 | 0.10 | 2 天 | 原话保留，较快退出日常召回 |
| 兴趣 | 0.35 | 30 天 | 近期再次提及可增强 |
| 普通事件 | 0.40 | 14 天 | 事实与结果分别有来源 |
| 用户事实 | 0.55 | 180 天 | 新证据或纠正更新，不凭衰减判为假 |
| 共同经历 | 0.65 | 90 天 | 助手单方叙述不成立 |
| 重要事件 | 0.75 | 90 天 | 重要性须有用户证据 |
| 进行中的计划 | 依来源判断 | 暂不衰减 | 直到完成、取消或过期；之后按事件计算 |
| 明确规则 | 不适用 | 不衰减 | 始终由规则路径生效 |

可核验的补充信号：用户明确强调重要性加 0.15，说明持续影响加 0.10，不同日期再次确认每次加 0.10、累计最多加 0.20。用户明确要求“记住”时令 I 至少为 0.80、半衰期至少为 180 天。总值封顶为 1。模型自行重复、夜间反思、仅被检索命中或仅注入提示词都不增加 I；敏感性也不增加 I。后续确需强化联系时，只计用户新证据或可核实的实际使用，并设置上限与冷却。

普通经历的半衰期 H = H0 × (1 + 4I)，明确要求记住时再应用 180 天的下限。距离最近一次有效用户证据 t 天时，时间因子 D = 2^(-t/H)；初始证据就是该记忆的来源原话，用户在不同日期再次确认时更新证据时间。本轮话题相关性 R 为 0～1，召回强度 A = R × (0.2 + 0.8I) × D。R 的初值约定：直接询问某事件为 1；交接中的明确指代约 0.9；同对象和同话题约 0.8；仅同话题约 0.6；弱关联约 0.4；无关为 0。R 小于 0.35 时不作日常召回。直接询问时允许沿来源取完整原话，不受日常淡化档位限制。检索先做结构化与中文文本候选，再评估相关性；取值和落选原因写入 RecallLog 供调参。

| A 的初始范围 | 本轮处理 |
| --- | --- |
| A ≥ 0.75 | 提供有时间、状态及来源的事件细节 |
| 0.50 ≤ A < 0.75 | 提供有来源的概要 |
| 0.25 ≤ A < 0.50 | 线索只供内部继续检索；证据不足时不据此陈述细节 |
| A < 0.25 | 日常不召回，原始证据仍按保留规则存在 |

例：普通闲聊以 I = 0.10、H0 = 2 天进入记忆流，即使当时相关，约一周后通常低于日常召回门槛；重要事件以 I = 0.75、H0 = 90 天计算，半年后若话题直接相关，通常仍能提供概要。该示例只验证公式趋势，不能代替中文真实对话评测。

## 7. 投影、召回与防过量

detail 由权威事件与来源整理，保留必要时间、经过和结果；gist 保留足以识别事件的核心；cue 只用于找回事件，不允许模型仅凭一个主题词编造经过。三个视图带相同来源版本，仅在事件新增、更正、合并或删除时重建；不从上一次概要递归生成下一次概要。

普通回复先加载硬规则、当前消息、近期原文和有效交接；随后在当前用户与角色的有效记忆中找候选，按证据、相关性和强度排序，必要时沿合法联系最多扩一跳。首版每轮最多注入约 3～5 条、500～800 字，话题无关时可以为零。进行中的待跟进可作为候选理由，但主动联系仍须通过授权、安静时段、频率、未回复退避及临发送前复核。私密内容需要更明确的当前话题证据；不因其情绪强烈而主动提及。

召回日志区分“检索到”“注入上下文”“回复实际采用”，记录作用域禁止、已删除或被取代、相关性不足、冷却、数量与预算上限等落选原因。仅检索到或注入过不能强化记忆。定期比较有无分层召回的回复质量，若复杂机制只导致翻旧账，就移除该机制。

## 8. 更正、结束、忘记与恢复

新消息可能是同一事实的补充、计划状态变化、旧话纠错，或无法判断的冲突。仅对真正可变化的属性使用 fact_key；事件流水通过有证据的 before、updates 等联系保留前后经过。冲突无法判明时置 disputed 并请用户确认，不能靠文字相似度覆盖旧事实。当前事实更新后，旧版本可作历史，但不得继续驱动当前计划或主动跟进。

自然淡化只改变日常取用，不删除内容。用户要求忘记时需区分“停止记住／提及”与“删除原始聊天”的范围：前者使权威记忆、投影、联系、交接和待跟进失效，并屏蔽旧来源再次提取；后者还按明确范围清理原文。若一个消息含多件事，优先精确屏蔽来源片段；无法可靠分段时保守地屏蔽整条消息的记忆检索。删除标记只保留必要来源标识，不复制已删除的秘密文字。版本检查阻止在途夜间任务写回旧内容；失败要可见并可重试。

导出与恢复阶段应携带原文、权威记忆、来源、状态、版本、联系、偏好和跟进；概要与检索索引可重建。完整资料包不含 QQ 或模型密钥。删除后从旧备份导入是否允许恢复该内容，须在导入规则中明确，不能悄悄复活。

## 9. 建设顺序与验收

| 步骤 | 交付 | 聚焦验证 |
| --- | --- | --- |
| P1 数据契约 | 标签、状态、来源、版本、任务水位和 SQLite 迁移；合成对话回放 | 旧数据库无损升级；同一消息重复输入不产生重复记忆；角色作用域正确 |
| P2 整理管道 | 暂歇聚合、候选提取、夜间巩固、失败重试及来源校验 | 玩笑和推测不变事实；停机补做不漏不重；模型错误不污染权威库 |
| P3 分层召回 | detail/gist/cue、相关性、强度、预算、交接和召回诊断 | 跨天能想起相关事件；闲聊不乱翻旧事；直接追问能核对原话 |
| P4 状态联动 | 更正、争议、计划结束、忘记、来源屏蔽与待跟进联动 | 旧状态不作当前事实；删除后从上下文、历史工具、夜间任务和主动联系均不能复现 |
| P5 平台与体验 | 终端和 AstrBot 共用服务；真实连续试用、成本与对照记录 | QQ 重启后承接、主动候选合规；比较“近期上下文”“增加记忆”“增加交接与联系”的效果 |

使用合成消息、可控时钟和临时数据库覆盖计算边界；再运行现有单元测试与独立的真实模型专项测试。真实 QQ 验证使用已绑定的单角色私聊，但测试消息与用户私人记忆分开记录。每类模型调用分别记录时延、token、费用和错误，不在日志默认打印完整私聊。

首轮场景至少包括：跨天面试与结果、计划取消、称呼纠正、模糊冲突、普通闲聊七天后不主动提起、重要经历半年后相关召回、旧事直接追问、玩笑与角色虚构、连续重复检索、私密信息误提、删除防复现及停机补做。评估分类为“应想起未想起”“不该提却提了”“记错仍笃定”“记对但表达不自然”。隐私、删除与角色隔离违规必须单独列为阻断项；强度参数需经至少一段连续试用和固定场景对照后调整。

## 10. 待实测校准的参数

30 分钟暂歇窗口、03:00 夜间任务、三天关联回看范围、各类型基础重要性与半衰期、R 的取值、四档阈值及每轮预算均为首版默认值。调整时记录旧值、新值、失败用例和效果；不能只凭一次“感觉更像人”的回复改参数。设计始终保留用户可核对和纠正的来源，不以模拟人脑为理由降低事实准确性或删除保障。
